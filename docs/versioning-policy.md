# Versioning policy

White Lab Neuro uses version control to help track the development of pipelines, protocols and project-linked resources over time.

## General principles

- Important methodological changes should be documented clearly
- Pipelines and protocols should include version notes where appropriate
- Project-linked outputs should ideally reference the workflow or protocol versions used
- Where possible, manuscript-linked analyses should be traceable to the relevant repository state

## Practical approach

As the repository grows, more formal versioning conventions may be introduced for:

- pipelines
- protocol releases
- project snapshots linked to manuscripts or datasets

## Early-stage approach

In the early stages of the lab, a lightweight versioning approach is acceptable so long as changes are documented clearly and files are organised consistently.

Useful practices include:

- keeping informative commit messages
- updating README files when structure changes
- noting major changes to methods or workflows
- linking projects to relevant pipeline or protocol locations where possible

## Future development

As White Lab Neuro grows, this policy may be expanded to include more formal release practices, manuscript-linked version tags and clearer citation guidance.
