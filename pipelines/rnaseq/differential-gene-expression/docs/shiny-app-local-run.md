# Shiny app local run

This document explains how to run the Shiny app output generated by `nf-core/differentialabundance` locally for a White Lab downstream bulk RNA-seq study.

The pipeline can generate a ShinyNGS-based application as part of the standard downstream output set. In White Lab practice, this is a useful interactive layer for:

- browsing differential results
- exploring study outputs without opening many separate files
- reviewing results with collaborators
- supporting lab discussion and handover

This page focuses on **local use of the generated app**, not external deployment.

---

## Why this output matters

The Shiny app is one of the most practically useful outputs of the downstream workflow because it provides an interactive way to explore:

- contrasts
- significant genes
- expression summaries
- report-linked data views

For many studies, this is easier to use for review and discussion than working directly from raw tables alone.

In White Lab practice, the app should be treated as a valuable exploration and communication layer, but not as a replacement for:

- the main differential result tables
- the HTML report
- the retained run metadata
- the study interpretation notes

---

## Where the Shiny app is generated

When `shinyngs_build_app: true` is enabled, the pipeline generates a Shiny app under:

`shinyngs_app/[study_name]/`

within the output directory.

Typical contents include:

- `app.R`
- `data.rds`

This is the runnable local app bundle produced by the workflow.

## What is required to run the app locally

To run the app locally, the environment must have the required R / Shiny / ShinyNGS dependencies available.

The pipeline output itself does not automatically make the app executable on any arbitrary shell session. A suitable R environment is still needed.

In White Lab practice, that usually means running the app from an environment where ShinyNGS and its dependencies are installed.

---

## Core launch principle

The app should normally be launched from within its own generated app directory.

That directory contains:

- `app.R`
- `data.rds`

The simplest local launch pattern is:

    cd /path/to/shinyngs_app/[study_name]/
    Rscript app.R

If the environment is configured correctly, this will return a local address such as:

    Listening on http://127.0.0.1:xxxx

which can then be opened in a browser.

## Suggested White Lab workflow for local use

A sensible local workflow is:

1. activate the R environment needed for Shiny / ShinyNGS
2. change into the generated app directory
3. launch the app with `Rscript app.R`
4. open the returned local URL
5. use the app for interactive review
6. stop the app with `Ctrl+C` when finished

This keeps app usage simple and reproducible.

---

## How to stop the app

When running locally in a shell session, the app can normally be stopped with:

    Ctrl+C

This ends the R process and releases the local port.

## What the app is useful for

In White Lab downstream studies, the local Shiny app is especially useful for:

- interactive browsing of the validated DGE run
- reviewing result behaviour with less command-line overhead
- checking contrasts alongside tables and plots
- discussing outputs during meetings
- giving collaborators a more accessible interface to the results
- comparing the baseline DGE app with an extension app such as Hallmark GSEA

This is one of the reasons `shinyngs_build_app: true` is a good default for most standard runs.

---

## What the app is not for

The Shiny app should not be treated as:

- the sole retained output of the study
- the only place where conclusions are drawn
- a substitute for examining the main result tables
- a replacement for the HTML report
- a replacement for run manifests, retention notes, or study summaries

It is best understood as an interactive interface to the study outputs.

---

## Suggested White Lab use pattern across runs

For studies with more than one downstream run, the app can also help show how the project evolves.

For example:

### Baseline DGE run
Use the app to explore the core contrast and differential result set.

### Hallmark extension run
Use the second app to explore the same study with the additional pathway-layer outputs generated by the extension run.

This can be especially useful for teaching and handover because it shows how a validated baseline run and a mechanistic extension run relate to one another.

---

## Common issues

### App does not start because R dependencies are missing
This usually means the shell environment does not contain the required Shiny / ShinyNGS packages.

### App starts but cannot be opened
This may be a local environment or browser-access issue rather than a pipeline-output issue.

### Wrong app directory used
Make sure you are launching from the generated study-specific app directory that contains both `app.R` and `data.rds`.

### Confusing the baseline app with an extension app
Always check which output directory the app belongs to, especially when multiple downstream runs exist for the same study.

---

## Recommended documentation practice

When a study generates a Shiny app, it is good practice to record:

- which run produced it
- where it is located
- whether it was reviewed successfully
- whether it is worth retaining as part of the study package

This should usually be reflected in:

- the output summary
- the retention summary
- the study-level metadata notes

---

## Relationship to retention

Where useful, the generated Shiny app should usually be considered for retention alongside:

- the HTML report
- the main differential result tables
- key plots
- pipeline provenance files
- run manifests and study summaries

This is particularly valuable when the app improves later study exploration or handover.

---

## Summary

The local Shiny app is one of the most useful interactive outputs produced by the White Lab downstream DGE workflow.

To run it locally:

1. activate the required R / Shiny environment
2. change into the generated app directory
3. run:

    Rscript app.R

For the Klim example, both the baseline DGE run and the Hallmark extension run now provide real Shiny app outputs that can be used for interactive review.

The app should be treated as a strong exploration and communication layer, but always as a companion to, not a replacement for, the core downstream result tables and study documentation.
