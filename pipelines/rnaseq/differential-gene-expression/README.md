# differential-gene-expression

Reusable White Lab downstream bulk RNA-seq differential gene expression pipeline resources.

This repository section is the downstream companion to `pipelines/rnaseq/nfcore-rnaseq-processing/`. It is designed for reproducible differential gene expression (DGE) analysis starting from retained primary-processing outputs, rather than from raw FASTQ files.

The aim is to provide a reusable, well-documented lab resource for training, onboarding, and real project setup across the White Lab RNA-seq workflow stack.

---

## Purpose

`differential-gene-expression/` provides the reusable structure, templates, documentation, and worked examples needed to perform downstream gene-level differential expression analysis on bulk short-read RNA-seq datasets.

This repo section is intended to help users:

- start from retained outputs generated by the upstream preprocessing pipeline
- understand which files are required for downstream DGE
- organise a new analysis project reproducibly
- apply consistent modelling and reporting practices
- interpret differential gene expression outputs carefully
- separate reusable repo resources from live CREATE analysis projects

This is a lab resource, not a one-off analysis directory.

---

## Position in the White Lab RNA-seq workflow

The White Lab short-read RNA-seq workflow is organised in layers.

### Upstream layer
`pipelines/rnaseq/nfcore-rnaseq-processing/`

This upstream pipeline handles:

- raw FASTQ intake
- sample sheet setup
- reference selection
- alignment and quantification
- primary QC
- provenance capture
- retention of processed outputs for downstream analysis

### Downstream layer
`pipelines/rnaseq/differential-gene-expression/`

This downstream pipeline handles:

- intake of retained preprocessing outputs
- downstream sample-level QC for expression analysis
- count matrix selection and preparation
- experimental design definition
- differential gene expression modelling
- result extraction and annotation
- interpretation, export, and reporting

In other words:

raw FASTQ files do **not** start here.

This repo begins once an upstream preprocessing run has already been completed and its key retained outputs have been organised for downstream use.

## Expected starting inputs

This downstream DGE workflow is designed to start from retained preprocessing outputs produced by the White Lab `nfcore-rnaseq-processing` workflow.

Typical required inputs include:

- gene-level count matrices
- transcript-to-gene mapping where relevant
- sample metadata
- run metadata / provenance files
- retained preprocessing QC summaries for reference
- pipeline information documenting how the upstream outputs were generated

For most standard gene-level DGE workflows, the key retained inputs will come from the upstream Salmon merged quantification outputs.

Examples of important retained upstream files include:

- `salmon.merged.gene_counts.tsv`
- `salmon.merged.gene_counts_scaled.tsv`
- `salmon.merged.gene_counts_length_scaled.tsv`
- `salmon.merged.gene_tpm.tsv`
- `salmon.merged.gene_lengths.tsv`
- `salmon.merged.gene.SummarizedExperiment.rds`
- `sample_metadata.csv`
- `run_metadata.yaml`
- `samplesheet_with_bams.csv`
- `run_manifest.txt`
- `pipeline_info/*`
- `multiqc_report.html`

The exact file used for modelling will depend on the downstream method and the analysis question. This repo will document those decisions explicitly.

## Repository structure

The structure of this repo section is intended to mirror the logic used in the preprocessing pipeline.

### `README.md`
Top-level overview of purpose, structure, and usage.

### `docs/`
Detailed documentation, onboarding guides, workflow explanations, modelling notes, and interpretation guides.

Examples may include:

- downstream workflow overview
- required retained inputs
- count matrix selection guide
- metadata preparation guide
- design formula guide
- contrast design tutorial
- DGE QC and interpretation guide
- outputs guide
- CREATE project setup guide

### `configs/`
Reusable configuration or reference files for downstream analysis defaults.

These should contain stable reusable settings, not project-specific one-off edits.

### `templates/`
Starter files for new downstream DGE projects.

These are intended as the clean starting point for users creating a new real analysis outside the repo.

Typical examples may include:

- analysis directory skeleton
- metadata template
- run manifest template
- configuration template
- script or R Markdown starter templates

### `scripts/`
Reusable helper scripts only.

This directory should contain shared utilities that are appropriate across projects, not bespoke one-off project code.

### `examples/`
Worked examples that demonstrate how the pipeline structure is used in practice.

These examples are documentation and training resources, not the template source for new studies.

### `examples/klim2019_tdp43kd/`
The first worked example for this repo section, built from the retained outputs of the completed White Lab preprocessing example based on Klim et al. 2019 human iPSC-derived motor neuron RNA-seq in a TDP-43 knockdown setting.

### `decisions/` *(optional, to be confirmed)*
A place for short design notes capturing important repo-level decisions, conventions, or rationale.

This may be useful if we want to document why certain matrices, modelling defaults, naming conventions, or file standards were chosen.

---

## Relationship between templates, examples, and live projects

A central principle of this repo is clear separation between reusable source material and real execution environments.

### `templates/`
Contains clean starting material for new users and new studies.

### `examples/`
Contains finished worked examples to teach the structure and show what good practice looks like.

### Live CREATE / RDS projects
Real analyses should be launched and run outside the repo, using the repo as the reusable source of templates, documentation, and helper resources.

The repo should therefore remain clean, stable, and reusable.

## First worked example

The first worked example for this downstream DGE repo will be based on:

- **Example dataset ID:** `klim2019_tdp43kd`
- **CREATE project ID:** `Klim_TDP_LOF`

This example follows on from the completed upstream preprocessing example in:

`pipelines/rnaseq/nfcore-rnaseq-processing/examples/klim2019_tdp43kd/`

The upstream preprocessing run was completed successfully on CREATE and retained for downstream use. This DGE example will therefore demonstrate the intended handoff from upstream processed outputs into downstream statistical analysis.

The worked example will be educational as well as practical, showing:

- which retained preprocessing outputs are used
- how metadata is brought forward
- how design and contrasts are defined
- how DGE outputs are generated, annotated, and interpreted
- how downstream analysis deliverables should be organised
