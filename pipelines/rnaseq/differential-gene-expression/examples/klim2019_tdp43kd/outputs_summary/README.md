# Outputs summary

This directory contains curated notes describing the outputs generated by the downstream `klim2019_tdp43kd` worked example.

Its purpose is not to duplicate the full live CREATE output directory. Instead, it should provide a concise and educational summary of what the run produced, what was most important, and how those outputs should be understood in White Lab practice.

---

## Purpose of this directory

This directory is intended to help users understand:

- which output directory corresponds to the main Klim downstream run
- which output types were generated
- which outputs were most important for first-pass review
- which outputs were most important for retention
- how the Klim example maps onto the general `outputs-guide.md` documentation

This makes the example easier to use as a training resource and reference case.

---

## What should eventually be recorded here

Once the first real CREATE validation run is completed, this directory should usually contain short markdown summaries covering:

- the main output directory name
- the major result classes produced
- the key report outputs
- the key differential result tables
- whether pathway outputs were generated
- whether the Shiny app was generated
- whether the run produced the expected files cleanly

Examples of useful summary files may include:

- `initial_run_outputs.md`
- `report_outputs.md`
- `differential_results_summary.md`
- `pathway_outputs_summary.md` (if relevant)

## Initial expected run

For the first Klim downstream validation run, the expected output focus is:

- standard gene-level differential expression
- HTML report generation
- Shiny app generation
- no pathway layer in the initial run

This means the first output summary should focus primarily on:

- run completion
- exploratory outputs
- differential result tables
- HTML report
- Shiny app
- pipeline provenance outputs

## Relationship to the full live CREATE output directory

The full CREATE run output directory will remain the complete live execution result.

This directory should instead provide a curated summary for the repo example.

In simple terms:

- live output directory = full result tree
- `outputs_summary/` = educational summary of what matters most
